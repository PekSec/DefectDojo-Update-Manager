## Decided
The README's Docker Compose log commands explicitly target .runtime/compose.json, the private deployment generated by the manager with pinned image digests and loopback ingress. These commands only read initializer/worker logs. They are permitted troubleshooting commands.

## Tried and ruled out
The prohibition is specifically against deploying releases/*/docker-compose.yml directly or relying on its example secrets/latest defaults. It does not prohibit the Docker Compose executable, the word Compose in documentation, or read-only log inspection of the generated deployment.

## Watch out
trail check initially marked the README as bringing back upstream example Compose. That is a documentation false positive: no such deployment command exists. Assess the -f target and operation, not the executable's name. New release paths remain gated by real rehearsal evidence.
